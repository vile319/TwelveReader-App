# Inflect v2 TTS

A second local voice engine, added because Kokoro-82M does not reliably run in
iOS Safari. Inflect v2 is a VITS-family end-to-end text-to-waveform model at
4M/9M parameters, Apache-2.0, from [Owen Song](https://huggingface.co/owensong).

| | Kokoro 82M | Inflect Nano v2 | Inflect Micro v2 |
|---|---|---|---|
| Params | 82M | 3,966,721 | 9,356,513 |
| Weights | ~82MB (q8) | 16.21MB (FP32) | 37.75MB (FP32) |
| Voices | 50+ | 1 fixed male | 1 fixed male |
| iPhone | unreliable | target | should work |
| Upstream CPU speed | — | 10.72x realtime | 6.28x realtime |

## How to use it

Processing mode → **Local CPU**, then **Local voice engine**. The default is
`Automatic`: Inflect Nano on iOS, Kokoro everywhere else. Nothing changes for
cloud or WebGPU users.

## Layout

```
utils/inflect/
  symbols.ts     symbol table + tokenizer (port of runtime/text/symbols.py)
  numbers.ts     num2words-compatible English number speller
  normalize.ts   port of normalize_text from inflect_nano_v2_frontend.py
  phonemize.ts   espeak-ng via phonemizer.js + PHONEME_OVERRIDES
  chunk.ts       split_text, boundary pauses, edge fades
  rng.ts         seeded Gaussian latent noise
  InflectTTS.ts  the engine — two ONNX sessions, kokoro-js-shaped API
utils/ttsEngine.ts   facade that routes the hook to either engine
```

The hook (`useKokoroWebWorkerTts.ts`) is otherwise untouched: it always only
used `from_pretrained`, `generate(text, { voice })`, and `list_voices()`, so
both engines are served through that same shape.

## Known deviations from the Python reference

Three things differ, and it is worth knowing which are cosmetic and which are not.

**1. Latent noise RNG — expected, harmless.** Python uses
`np.random.default_rng(seed).standard_normal(...)`, i.e. PCG64 plus numpy's
ziggurat sampler. We use splitmix32 plus polar Box-Muller. The distribution is
the same, so speech quality is unaffected, but a given seed produces *different*
audio here than in Python. Seeds remain reproducible within this app. There is a
test asserting mean ≈ 0 and variance ≈ 1 over 200k samples.

**2. espeak-ng build.** Python links the Linux `libespeak-ng.so`; we use
Xenova's WASM build via `phonemizer`. Same engine, potentially different
version. Two mitigations are in place: language-switch markers like `(fr)` are
stripped (Python passes `language_switch="remove-flags"`, which phonemizer.js
lacks), and any symbol outside the 177-entry vocabulary is dropped with a
console warning rather than throwing a `KeyError` mid-book.

**3. Sentence splitting avoids lookbehind.** Python uses
`(?<=[.!?;:])\s+`; Safari only gained lookbehind in 16.4 and this app targets
older iPhones, so `chunk.ts` splits by hand. Verified equivalent against the
Python output for the fixture corpus.

## The apostrophe quirk

`_letters_ipa` contains the ASCII apostrophe **twice** (positions 174 and 176).
The reference builds its lookup with a dict comprehension, so the later index
wins: `"'"` maps to **176**, and the map has 177 keys for 178 symbols. This is
reproduced exactly in `symbols.ts` — the embedding table was trained against
these IDs, so "fixing" it would mispronounce every contraction. There is a test.

## Tests

`__tests__/inflect.test.ts` — 45 tests. The fixtures in
`inflect.fixtures.json` were generated by running the **actual Python reference
implementation** over a corpus, not hand-written. If the port drifts from
upstream, these fail.

```bash
npm test
```

Covered: symbol table identity and ordering, the apostrophe quirk, blank
interleaving, num2words parity, 18 `normalize_text` cases, 5 `split_text`
cases, boundary pauses, edge fades, concat/clipping, and RNG distribution.

## Not verified — check these on a real device first

Everything above is verified by unit tests or by reading the reference
implementation. The following could not be tested in CI and are the real
remaining risk:

- **Actual audio output.** No end-to-end synthesis has been run. The graph I/O
  names (`tokens`, `lengths`, `length_scale` → `m_p_exp`, `logs_p_exp`,
  `y_mask`; then `+ zp_noise`, `noise_scale` → `waveform`) come from upstream's
  `onnx/inference_onnx.py` and should be right, but confirm on first run.
- **onnxruntime-web 1.17.3 opset support.** The pinned version is old and chosen
  for iOS stability. If session creation fails with an unsupported-op error, the
  ORT version is the first thing to bump.
- **iOS throughput.** Upstream's 6.28x/10.72x figures are 8 vCPU with 4 threads.
  iOS runs single-threaded with SIMD disabled (`InflectTTS.from_pretrained`
  forces this). Nano is the safe starting point; treat Micro as unproven there.
- **WebGL is deliberately not used.** The decoder is a HiFi-GAN-style stack and
  the WebGL EP has no `ConvTranspose`, so Inflect always requests `wasm` even
  when `onnxIosConfig` prefers WebGL for Kokoro. Do not "restore" WebGL here.

## Why the model is small

Not quantization: 9,356,513 params x 4 bytes = 37.43MB against a stated
37.53MB, so it is plain FP32. The size comes from architecture and data —
narrow channels (text hidden 96, latent 192, 3 encoder layers, decoder initial
320), a single fixed synthetic voice so no speaker embeddings or multilingual
phoneme space, end-to-end VITS rather than acoustic-model-plus-vocoder, and
espeak-ng handling the linguistics outside the network.

Upstream does not publish INT8/INT4: naive weight quantization audibly damages
the integrated waveform decoder. If you are tempted to shrink these further,
that is the documented reason not to.
